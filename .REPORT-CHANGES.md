## 1. CVE research + new Fast Pair Model IDs

### CVEs / research reviewed
| Subject | Verdict |
|---|---|
| **WhisperPair / CVE-2025-36911** (KU Leuven, Jan 2026) — forced Fast Pair pairing, hijack + tracking | GATT/pairing-level attack (laptop/RPi), not advertisement-based; OTA PoC not published → **not replicable** in an advertisement-only app. However, their public `model_ids.csv` is a recent ID source → **used (see below)** |
| **CVE-2026-20650** (Apple, Bluetooth DoS, iOS 26.3) | No payload details published by Apple → **not implementable** |
| **CVE-2026-44634** (SimpleBLE: overflow while parsing manufacturer/service data) | Our advertisements are valid by construction, and the edit dialog already allows crafting arbitrary payloads to test parsers → **already covered** |
| Current Momentum `ble_spam` firmware (continuity/easysetup/swiftpair/lovespouse/fastpair) | Full parity verified by diff (15 Continuity actions, Buds/Watch, SwiftPair, Lovespouse). Only missing protocol: **NameFlood** → **rejected**: the Android API cannot customize the Complete Local Name per advertisement (would require renaming the phone's own BT adapter — too intrusive) |

### Effective additions
- **+513 Fast Pair Model IDs** (2024–2026, source: `https://github.com/KULeuven-COSIC/WhisperPair/blob/main/model_ids.csv`) in `FastPairDevicesAdvertisementSetGenerator._genuineDeviceIds` (467 → **980 distinct IDs**, variants capped at 3/name): WH-1000XM6, Pixel Buds Pro 2, Nothing Ear (a), OnePlus Nord Buds 3 Pro, ULT WEAR, LinkBuds Fit/Open, WF-C510, WH-CH720N, Bose QC Ultra / Ultra Open / SoundLink, JBL Tune Beam 2 / Flip 7 / Charge 6 / Go 4 / Clip 5 / PartyBox / Tour / Live Beam 3, Marshall Monitor III / Major V / Emberton III / Middleton II / Woburn III / Kilburn III / Acton III, Technics, EarFun, CMF, OPPO Enco, realme, Xiaomi/Redmi, Jabra Elite 8/10 Gen 2, Sonos Ace, Philips, LG xboom, Skullcandy, Beyerdynamic, B&W, Focal, Audio-Technica, AKG, Edifier…
- **+6 Phone Setup IDs** (`FastPairPhoneSetupAdvertisementSetGenerator`): Galaxy S21+/S21 Ultra 5G, A34/A14/A24/M34 5G.
- **Auto-sync on startup** (`DeviceCustomizationHelper.syncMissingDefaults()`, called on IO in `MainActivity.onCreate`, once per process, race-guarded against seeding): existing installs receive the new devices **without losing** deletions, edits, or customs.

## 2. Delete / edit devices (all categories)

Every device row (Fast Pair, Continuity, Swift Pair, Easy Setup, Lovespouse, Kitchen Sink) now has **edit** and **delete** buttons.

### 2.1 Per-row UI
- `app/src/main/res/layout/list_item_advertisement_set.xml` — switched to horizontal: `TextView` (weight 1) + two 40dp `ImageButton`s (`listItemAdvertisementSet{Edit,Delete}Button`, `focusable=false`, `blocksDescendants` so row clicks keep working).
- `app/src/main/res/drawable/ic_edit.xml`, `ic_delete.xml` — Material vector icons.
- `Adapters/AdvertisementSetCollectionExpandableListViewAdapter.kt` — `OnAdvertisementSetActionListener` interface, extended holder, blue (`blue_normal`) color when `selected` and not currently advertising (green/red status colors keep priority).

### 2.2 Generic edit dialog
- `app/src/main/java/.../ui/advertisement/EditAdvertisementSetDialog.kt` — edits **title**, **manufacturer payloads** (ID + hex), **service payloads** (UUID + hex), **Include device name / TX power** checkboxes. Built dynamically from the set's content (N entries). Blocking validation: empty title, invalid even-length hex, manufacturer ID > FFFF, invalid UUID (dialog stays open + toast).

### 2.3 Persistence (no schema migration)
- **DAOs** (additive queries only): `AdvertisementSetDao` (`findByIdOrNull`, `updateTitle`, `deleteById`), `AdvertiseDataDao` (`updateFlags`, `deleteById`), `AdvertiseDataManufacturerSpecificDataDao` (`updateEntry`, `deleteByAdvertiseDataId`), `AdvertiseDataServiceDataDao` (`updateEntry`, `deleteByAdvertiseDataId`), `AdvertiseSettingsDao` / `AdvertisingSetParametersDao` / `PeriodicAdvertisingParametersDao` (`deleteById`).
- `Helpers/DatabaseHelpers.kt` — `getAdvertisementSetById()`, `getAllAdvertisementSets()`, `updateAdvertisementSetContent()`, `deleteAdvertisementSetTree()` (cascading delete of related rows, no orphans).
- `Helpers/DeviceCustomizationHelper.kt` *(new, object)* — soft-delete by stable row id (`deleted_ids` in `SharedPreferences`), JSON backups of pre-edit original state (`backup_<id>`), `filterDeleted()`, `matchesBackup()` (manually reverted sets drop their "modified" entry), `defaultGenerators()` / `defaultSetsByKey()` / `identityKeyOf()` / `isDefaultSet()`, `resetToDefaults()`, `syncMissingDefaults()`.
- `Database/AppDatabase.kt` — seeding reuses `DeviceCustomizationHelper.defaultGenerators()` (single source of defaults, identical behavior).
- `AdvertisementCollectionFragment.buildAdvertisementCollection()` filters deleted sets; `AdvertisementFragment.refreshCurrentCollectionFromDatabase()` reloads from DB, pushes to the queue handler, cleanly deactivates if the list becomes empty mid-spam.

## 4. Multi-selection

Tap = toggle: previously tapped devices **stay selected** (blue), re-tap = removed.

- `Models/AdvertisementSet.kt` — `selected` flag (session only, not persisted).
- `Handlers/AdvertisementSetQueueHandler.kt`:
  - `_selectedIds` (stable ids), `toggleSelectedAdvertisementSet()` (returns new state), `isSelected()`, `getSelectedIds()`, `clearSelection()`, `retainSelection()`, `findSetById()`, `getSelectedOrdered()` (collection order), `getCurrentAdvertisementSet()` / `clearCurrentAdvertisementSet()`, `setSetsSelected()` (bulk).
  - `setAdvertisementSetCollection(collection, clearSelection = true)` — navigation clears the selection, refresh preserves it (`false`).
  - `selectNextAdvertisementSet()`: non-empty pool → `selectNextFromPool()` (Linear/List = pool cycle, Random = draw from pool, Single = repeat last tapped, fallback to first selected); otherwise original logic untouched.
- `AdvertisementFragment` (`setOnChildClickListener`): toggle + `setSelectedAdvertisementSet` when selected (+ clear current when deselected) + `notifyDataSetChanged()`. Refresh preserves selection by id.
- Switching category resets the selection.

## 5. Custom Swift Pair name

Adds a free-form Swift Pair device name to the list (also works in the Kitchen Sink Swift Pair section).

**Files:**
- `app/src/main/res/values/strings.xml` — `swift_pair_custom_name_hint`, `swift_pair_add`, `swift_pair_custom_{added,empty,too_long,exists}`
- `app/src/main/res/layout/fragment_advertisement.xml` — `advertisementFragmentCustomSwiftPairContainer` (input + Add button, `gone` by default, shown when the collection contains Swift Pair; the Center layout is re-constrained below it)
- `app/src/main/java/.../ui/advertisement/AdvertisementFragment.kt` — `isSwiftPairCollection()` (+ "Swift Pair" title fallback when the list is empty), `onAddCustomSwiftPairDeviceClicked()`

**Behavior:**
- Generates a real `AdvertisementSet` via `SwiftPairAdvertisementSetGenerator` → persisted to DB → list reloaded, "N Devices" counter updated.
- Validation: empty rejected, duplicate (case-insensitive) rejected, **24 bytes max** (3 header bytes + name must fit the 31-byte legacy payload), `maxLength=24` on the field. Also submittable via the keyboard Done key.
- Survives restarts (stored in DB, no migration needed).

## 6. Long-press on category (bulk selection)

Long-press (> 500 ms = system long-press threshold) on a **category header**:
- incomplete category → **everything selected** at once;
- fully selected category → **everything deselected** at once;
- no popup, color follows; long-press on a single device = no-op (`false`).
- Implementation: `setOnItemLongClickListener` + `getExpandableListPosition` / `getPackedPositionType` / `getPackedPositionGroup` in `setupExpandableListView()`; `setSetsSelected()` in the handler; current cleared if it leaves the selection.
- Handy for large lists like Fast Pair (~1000 entries): one long-press on the header selects all.

## 7. Fixes: selection + edit button

| Bug | Cause | Fix |
|---|---|---|
| Tapping a name no longer selected | `ImageButton`s are focusable by default → row click broken in the `ExpandableListView` | `focusable=false`, `focusableInTouchMode=false`, `descendantFocusability=blocksDescendants` |
| Edit button silently did nothing | DB read on the UI thread → Room exception swallowed by `try/catch` | Load on `Dispatchers.IO`, then open dialog on UI thread + error toast if the row is gone |
| Audit | — | All other DB access already runs on IO (verified) |

## Notes & known limitations

- APK signed with the **debug** key (stock fallback, no `release.jks`): fine for sideloading, not for the Play Store. For a real release: provide `app/release.jks` + `STORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`, then rebuild.
- Remaining Kotlin warnings are pre-existing (`Condition is always ...`, deprecated `startActivityForResult`) plus 2 benign `Java type mismatch` warnings on backup JSON.
- WhisperPair itself, CVE-2026-20650, and NameFlood are not implementable in this app (see §1) — documented honestly rather than faked.
- Responsible use: only test your own devices or with explicit permission.
